START HERE — publish safely

This process does not require any coding tools or terminal commands.

1) Keep an untouched verified copy
- Keep one copy of this repository as your approved reference.
- Keep a second copy for edits and review.

2) Make a candidate copy
- Work only in the candidate copy during revision cycles.

3) Ask for updates using the right files
- Attach:
  - `AI_READ_FIRST.txt`
  - `MY_WEBSITE_FACTS.txt`
  - `CHANGE_REQUEST.txt`
  - the current complete site folder contents (`site/`)
- Ask for one complete replacement file set.

4) Apply the result
- Save only the files the AI returns to your candidate copy.
- Keep all files as full, complete replacements.

5) Review before publishing
- Open `site/index.html` in a browser.
- Open `site/meetings.html`, `site/about.html`, `site/newcomers.html`, `site/resources.html`, `site/connect.html`, and `site/404.html`.
- Confirm:
  - skip link works,
  - keyboard focus is visible,
  - mobile menu opens/closes,
  - no broken local navigation,
  - no missing files or broken images,
  - demo notice is present on every page.

6) Correct, approve, or repeat
- If anything is wrong, request a new complete file set and repeat review.
- Keep only an approved copy for publication.

7) Publish decision
- Never publish until all checks are approved by you personally.

7) What to verify first before going live
- `MY_WEBSITE_FACTS.txt` matches published copy,
- no fictional/placeholder details remain as if real,
- no real contact endpoint is shown unless verified,
- header, footer, and mobile menu are visible and usable.

Learner workflow reminder:
- The site is a static folder (`site/`) that includes multiple pages.
- No separate build step is required for local review.
